# 背景

集群不是训练专用的，要同时跑三种差别很大的负载：

- **[Coder](https://coder.com/) workspace**：给用户开的交互式开发环境，需要几个 CPU 核、几十 GB 内存，或者一两张整卡来跑仿真和调试；什么时候来、要多少、占多久都不确定；
- **分布式训练**：Agentic RL 的训练任务，需要跨节点用 GPU，拓扑一改动就得重启，所以跑起来就希望一直占着；
- **常驻 GPU/CPU 服务**：如模型部署，平时没什么流量也得挂着，流量来了要随时响应；

这三类负载要的东西不太一样：workspace 要能拿到并且用得上一段时间，训练要能占满并跨节点，服务要一直活着。如果按节点给它们分地盘，那每类负载都会在属于别人的节点上空着，集群利用率被最闲的那一类拖着走。

所以我不打算手动划分节点专门用于服务某类负载。需要保证的一点是 serving 不跟其他负载混跑：一部分节点的 GPU 专门用来跑部署，但这些节点的 CPU 和内存仍然要能接 CPU job。

另外，不同类型之间的负载基本不涉及到抢占：如果训练真的需要资源，直接去跟 workspace 用户和部署的使用方沟通，先把活停掉、把资源让出来就行。

剩下的问题就是怎么在不划分节点的前提下让这三类负载共用同一批机器，只在 GPU 上按卡隔开，CPU 和内存则照常复用。
